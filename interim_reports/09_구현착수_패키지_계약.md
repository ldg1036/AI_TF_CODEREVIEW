# 구현 착수 패키지 계약

## 1. 목적

이 문서는 바이브코딩 에이전트가 환경·데이터 모델·테스트 기준을 추측하지 않고 첫 구현을 시작하기 위한 실행 계약이다. 실제 Excel 구조는 `08_ADR_실제_Excel_양식_계약.md`를 우선한다.

## 2. 개발 환경과 의존성

| 항목 | 기준 |
|---|---|
| OS | Windows 10/11 64-bit |
| Python | 3.12 |
| Excel | `openpyxl>=3.1,<4` |
| GUI | `pywebview>=5,<6` |
| HTTP client | `httpx>=0.27,<1` |
| 패키징 | `PyInstaller>=6,<7` |
| 테스트 | `pytest>=8,<9` |

실제 프로젝트 생성 시 위 범위를 `pyproject.toml`에 고정하고 lock 파일을 함께 보관한다. 의존성 추가는 ADR 또는 변경 기록 없이 수행하지 않는다.

## 3. 표준 실행 명령

```text
python -m app.main --help
python -m app.main --input <file-or-directory>
python -m app.main --input <file> --rule-source <client-or-server.xlsx> --no-ai
pytest
python -m pytest tests/test_excel_rule_compiler.py -q
pyinstaller app.spec
```

GUI는 `python -m app.main`의 기본 모드로 실행하고, CLI와 GUI가 동일한 Core pipeline을 사용한다. 명령 실패 시 종료 코드와 JSON 오류 코드를 함께 반환한다.

## 4. 데이터 모델 최소 계약

구현자는 아래 필수 필드와 enum을 변경하지 않는다. 추가 필드는 하위 호환 가능하게 추가한다.

```yaml
RuleDefinition:
  required: [rule_id, source_key, file_types, checker_type, enabled, rule_version]
  enums:
    checker_type: [builtin, regex, manual]

Violation:
  required: [violation_id, rule_id, file_id, status, severity, message]
  enums:
    status: [FAIL, MANUAL_REVIEW, ERROR]
    severity: [Critical, High, Medium, Low, Info]

ReviewReport:
  required: [schema_version, run_id, rule_source, files, violations, errors, metrics]

ParseStatus:
  required: [status]
  enums:
    status: [parsed, parse_failed, unsupported]
```

실제 구현에서는 `schemas/*.json`과 Python dataclass를 함께 두고, 리포트 저장 전 JSON Schema 검증을 수행한다.

## 5. 레거시 매핑 프로파일 착수 기준

`config/legacy_mapping/client.yaml`과 `config/legacy_mapping/server.yaml`을 생성한다.

- Client 15개, Server 20개 항목을 모두 `source_key`로 나열한다.
- 승인된 자동 룰은 `rule_ids`와 `automation_mode`를 지정한다.
- 아직 checker가 없는 항목은 `automation_mode: manual`로 명시한다.
- 프로파일에 없는 항목, 중복 `source_key`, 존재하지 않는 `rule_id`는 컴파일 오류다.
- Excel SHA256과 프로파일 버전을 결과에 저장한다.

첫 구현에서는 checker를 임의로 추측하지 말고, 매핑되지 않은 항목을 수동검토로 남긴다.

## 6. 골든 샘플 계약

```text
tests/fixtures/
  ctl/positive/
  ctl/negative/
  pnl/positive/
  xml/negative/
tests/expected/
  <rule_id>.json
```

각 자동 룰에는 정상·위반·예외 샘플을 최소 1개씩 둔다. 기대 결과에는 `rule_id`, 상태, 예상 라인, 심각도, 메시지 템플릿을 포함한다. 룰·파서·Excel 매핑 변경 시 전체 골든 테스트를 다시 실행한다.

## 7. AI API 확정 체크리스트

실제 provider 구현 전 다음 값을 사내 인프라팀에서 확정한다.

- endpoint URL과 허용 HTTPS host/port
- 인증 방식과 비밀값 주입 방법
- 요청·응답 JSON 필드 및 streaming 여부
- 모델명·버전·컨텍스트 길이·최대 출력 토큰
- 429/5xx/timeout 재시도 가능 여부와 rate limit
- 코드·경로·개인정보의 전송 허용 범위

확정 전에는 `mock_provider`만 사용하고 실제 endpoint를 추측 구현하지 않는다.

## 8. 완료 게이트

- `pytest`가 통과한다.
- Client 15/15, Server 20/20 매핑 프로파일 검증이 통과한다.
- 유효·무효 `ReviewReport` fixture가 JSON Schema 검증을 통과한다.
- `python -m app.main --input ... --no-ai`로 서버 없이 JSON/HTML 결과가 생성된다.
- 실제 Excel 파일을 교체했을 때 SHA256 감지와 직전 정상 룰셋 롤백이 확인된다.
