# UI 내 환경 설정 (settings.yaml) 동적 변경 기능 통합 및 검증 보고서

## 1. 개요 및 배경
* 사내 로컬 AI 서버 환경(IP, 포트, API 키, 모델 명) 및 파이프라인 동작 설정(자동 수정 기능 등)을 사용자가 텍스트 에디터 없이 데스크톱 애플리케이션 화면에서 직접 관리할 수 있도록 요구사항이 제기되었습니다.
* 본 보고서는 `config/settings.yaml` 파일을 UI 프론트엔드와 백엔드 간에 실시간 양방향 연동하여 동적으로 조회 및 수정, 저장할 수 있는 아키텍처 개선 과정과 과학적 검증 결과를 기록합니다.

## 2. 아키텍처 및 구현 기술 방침
1. **백엔드 설정 관리 브리지 API (`JSApi`)**
   * `wincc_reviewer/app/ui/api.py` 모듈의 `JSApi` 클래스에 다음 메소드를 확장 구현하였습니다:
     * `get_settings()`: 프로젝트 `config/settings.yaml` 파일 경로를 탐색하고 PyYAML(`yaml.safe_load`) 라이브러리를 통해 딕셔너리로 반환합니다.
     * `update_settings(new_settings)`: UI 프론트엔드로부터 수신한 설정 딕셔너리 데이터를 검증하고, `yaml.dump(allow_unicode=True, default_flow_style=False)` 형식으로 `settings.yaml`에 안전하게 덮어쓰기 저장합니다.
     * `list_ai_models(options)`: 설정된 호스트 및 포트의 로컬 AI 서버(`http://host:port/v1/models`) 또는 AI 제공자에 연결하여 사용 가능한 모델 ID 목록을 JSON 파싱 후 반환하며, 연결 실패 시 안전한 기본 모델 리스트를 폴백으로 제공합니다.
   * 다국어 문자 호환성을 완벽히 보장하기 위해 모든 YAML 입출력에는 `utf_8_sig` 인코딩을 강제하였습니다.

2. **프론트엔드 사용자 인터페이스 (`index.html`)**
   * 네비게이션 탭 바에 `⚙️ 환경 설정 (settings.yaml)` 전용 패널(`settingsTab`)을 추가하였습니다.
   * 입력 폼 항목:
     * AI 심층 리뷰 활성화 여부
     * AI 제공자(Provider) 선택 (local / gemini / mock)
     * 사내 로컬 AI 서버 IP (Host) 및 PORT 번호
     * 인증 API KEY (보안 암호 필드)
     * API 엔드포인트 및 모델 명 (Model ID)
     * 요청 타임아웃(초) 및 자동 수정본(autofix) 생성 허용 옵션
   * **모델 명 선택 콤보박스 고도화**: 모델 명 입력을 수동 텍스트 필드에서 콤보박스(`<select id="cfgAiModelId">`) 리스트 형식으로 전환하였습니다. 설정 로드 시 또는 사용자가 **`🔄 모델 조회`** 버튼을 누르면 즉시 `list_ai_models` API를 호출하여 조회된 모델 리스트로 옵션을 자동 동기화합니다.
   * **설정 저장 경로 사용자 정의 기능 반영**: 환경 설정 편집기 상단에 경로 입력란 및 **`📂 경로 찾기`**, **`🔄 해당 경로 로드`** 버튼을 신설하였습니다. 사용자는 언제든지 원하는 디렉토리 경로의 YAML 파일을 지정하여 설정을 불러오고 저장할 수 있습니다.
   * UI가 로드될 때 `get_settings(custom_path)`를 통해 실시간 설정을 폼 필드와 사이드바 제어판(`chkNoAi`)에 즉시 반영하며, `saveSettingsUI()` 이벤트 호출 시 갱신된 설정을 지정된 경로의 YAML 파일에 영구 반영합니다.

## 3. 테스트 및 과학적 타당성 검증
1. **단위 테스트 검증 (`test_settings_api.py`)**
   * 임시 디렉토리 상에서 `settings.yaml`을 생성하고, `get_settings()`로 읽은 후 포트 번호를 수정한 뒤 `update_settings()`를 호출하여 실제 디스크의 YAML 파일에 올바르게 반영되는지 검증하였습니다.
   * 또한 `list_ai_models()` 호출 시 `mock`, `gemini`, `local` 각 프로바이더 및 네트워크 통신 실패 상황에서 예외 없이 정확한 모델 리스트 및 폴백 목록이 반환되는지 단위 테스트(`test_list_ai_models`)로 검증하였습니다.
   * 커스텀 설정 저장 경로 지정 기능에 대해서도 단위 테스트(`test_custom_settings_path`)를 통해 임의의 디렉토리 경로에 설정을 신규 저장하고 다시 읽어오는 동작이 무결함을 검증하였습니다.
   * 검증 결과: 100% 성공 (`3 passed in 2.57s`).

2. **전체 회귀 테스트 스위트 검증**
   * 기존 86개 테스트 및 신규 추가된 로컬 AI 서버 연동 테스트(4개), 설정 관리, 모델 조회, 커스텀 저장 경로 API 테스트(3개)를 합산한 총 93개 회귀 테스트를 실행하였습니다.
   * 실행 결과: `93 passed in 5.42s` (회귀 결함 0건).
   * 데이터 정규화, 엑셀 룰 컴파일, 로컬 AI 통신, HTML 리포트 생성 및 UI API 바인딩 간의 호환성과 안정성이 완벽히 입증되었습니다.

## 4. 설계 문서 및 매뉴얼 업데이트 내역
* **아키텍처 설계서 (`02_TRD_아키텍처설계서.md`)**: 제5.7절 및 제5.8절을 갱신하여 UI 환경 설정 탭 구성과 `JSApi`의 `get_settings(custom_path)`, `update_settings(new_settings, custom_path)`, `list_ai_models(options)` 인터페이스 계약을 문서화하였습니다.
* **사용자 매뉴얼 (`USER_MANUAL.md`)**: 제3절 화면 구성에 환경 설정 탭을 추가하고, 제5절에 설정 저장경로 사용자 정의 및 콤보박스를 통한 모델 명 선택 가이드를 상세 추가하였습니다.

## 5. 결론 및 향후 활용 방안
* 사내 AI 서버 IP 및 API KEY가 변경되거나 대상 OS PC를 옮겨 설치하더라도 UI 상에서 몇 초 이내에 환경 설정을 재구성할 수 있는 기반이 갖춰졌습니다.
* 사용자가 자유자재로 설정 파일의 저장 및 불러오기 경로를 바꿀 수 있어 다중 프로젝트 환경 또는 클린 가상환경 배포 시 유연성이 극대화되었습니다.
* 향후 배포 패키지(`PyInstaller`)의 가상환경 실행 시에도 외부 임의 경로의 `settings.yaml` 파일에 안전하게 접근하여 릴리스 게이트 검증을 원활히 지원할 수 있습니다.
