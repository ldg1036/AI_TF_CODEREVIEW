# WinCC OA 코드리뷰 자동화 프로그램 잔여 작업 및 향후 고도화 로드맵 명세서

## 1. 개요 및 작성 목적
* 본 문서는 WinCC OA 코드리뷰 자동화 프로그램(WinCC Reviewer)이 **119개 전체 회귀 테스트 스위트를 100% 통과(119 passed in 5.56s)**하며 달성한 프로덕션 레디(Production_Ready) 아키텍처를 기반으로, 향후 선택적으로 추진할 수 있는 **잔여 단기/배포 작업(2건)**과 **중장기 확장 작업(3건)**의 기술 명세와 완료 기준(DoD)을 과학적 타당성에 기초하여 정의합니다.
* 본 문서에 기술된 과제들은 현재 코드 베이스의 무결성을 손상하지 않도록 분리된 확장 모듈 형태로 설계되었으며, 향후 필요 시 추적성 손실 없이 즉시 착수할 수 있는 표준 명세 역할을 수행합니다.

## 2. 즉시 착수 가능한 단기 및 배포 마무리 잔여 과제

### 가. [단기 과제] UI 하단 실시간 시스템 환경 진단 및 자가 검증(Self_Check) 상태 배지 탑재
* **목적 및 타당성**: 제어 공정 현업 컴퓨터는 윈도우 OS 업데이트 상태, Python 런타임 설치 유무, WebView2 엔진 버전, WinMerge 경로 등이 다양하므로 프로그램 실행 상태와 도구 연결 상태를 직관적으로 판정할 자가 진단 체계가 필요합니다.
* **상세 설계 및 명세**:
  * **API 바인딩**: `app/ui/api.py` 내 `get_system_status()` 엔드포인트를 구현하여 현업 데스크톱의 4대 핵심 지표를 반환합니다.
    1. `python_runtime`: 현재 실행 엔진 버전 및 가상환경 상태
    2. `winmerge_available`: `WinMergeU.exe` CLI 실행 가능 여부 (True/False)
    3. `ruleset_validity`: Excel 룰 카탈로그(Client/Server) 파일 파싱 유효성
    4. `ai_online`: 로컬/원격 Gemini AI 서버 통신 응답 상태
  * **UI 렌더링**: `html/index.html` 하단 상태바(Status Bar)에 4색 칩(녹색: 정상, 황색: 폴백 동작, 적색: 오류)으로 상태를 표현합니다.
* **완료 기준(DoD)**:
  * 인위적인 경로 오류나 네트워크 단절 시 UI 하단 칩이 즉시 해당 상태를 감지하여 시각적으로 표기해야 합니다.

### 나. [배포 과제] PyInstaller 단일 실행 파일(.exe) 패키징 및 클린 윈도우 환경 최종 검증
* **목적 및 타당성**: 현업 컴퓨터에 별도의 파이썬 런타임이나 의존성 라이브러리를 설치하지 않고 즉시 배포할 수 있는 단일 윈도우 실행 파일(`.exe`) 산출물을 확정합니다.
* **상세 설계 및 명세**:
  * **빌드 스펙 설정**: `wincc_reviewer.spec` 파일을 사용하여 PyInstaller 빌드 시 다국어 파서, Excel 룰 양식, HTML 보고서 템플릿, pywebview 바인딩 애셋을 단일 실행 바이너리 내부에 번들링합니다.
  * **클린 가상환경 테스트**: 파이썬 인터프리터가 없는 윈도우 클린 OS에서 `.exe` 실행 시 단일 파일 검사, 배치 스캔, HTML/CSV 보고서 내보내기가 오류 없이 동작하는지 실증합니다.
* **완료 기준(DoD)**:
  * 생성된 단일 실행 파일이 외부 파이썬 환경 없이 100% 정상 구동되고, 스캔 및 보고서 산출 시 메모리 누수가 없어야 합니다.

## 3. 시스템 심층 확장을 위한 중장기 확장 과제

### 가. [중장기 과제 1] 대용량 시스템 로그 및 런타임 이상 행위(Memory Leak, Event Flooding) 상관분석 모듈
* **목적**: 정적 소스 코드 검사 결과와 WinCC OA 공정 런타임 로그(`PVSS_II.log`)를 결합하여 실제 장애 유발 함수를 역추적합니다.
* **상세 명세**:
  * 대용량 로그 파일에서 시간대별 에러 스파이크 및 이벤트 폭주(Flooding) 문자열을 파싱하는 고속 로그 파서 모듈(`app/core/log_analyzer.py`)을 구축합니다.
  * 정적 분석 룰 위반 위치(`file_id`, `line_start`)와 런타임 콜스택 로그를 상관 분석하여 고위험 후보군을 점수화합니다.

### 나. [중장기 과제 2] Ctrl_Extension (C++ DLL) 네이티브 바이너리 인터페이스 정적 검증
* **목적**: `.ctl` 스크립트에서 로드하는 확장 DLL 라이브러리의 함수 시그니처와 메모리 안전성을 정적으로 검사합니다.
* **상세 명세**:
  * `#uses` 구문으로 가져오는 DLL 파일의 익스포트 함수 시그니처와 스크립트 호출 매개변수를 교차 대조하여 호출 불일치로 인한 공정 크래시(Crash)를 예방합니다.

### 다. [중장기 과제 3] 사내 Git/SVN 연동 CI/CD 품질 게이트(Quality Gate) 자동화 파이프라인
* **목적**: 현업 엔지니어의 코드가 원격 저장소에 병합되기 전 자동화된 품질 통제를 적용합니다.
* **상세 명세**:
  * `wincc_reviewer --cli --quality_gate` Command_Line 인터페이스를 구축합니다.
  * `Critical` 위반 0건, `High` 위반 5건 이하 등의 사내 품질 기준 미달 시 Git/SVN 커밋 또는 Merge Request를 자동 거부하는 파이프라인 Hook을 완비합니다.
