# 미완료 기능 및 바이브코딩 지침서 부족 요소 상세 점검 보고서

작성일자: 2026년 8월 9일  
작성목적: WinCC OA Code Reviewer 프로젝트의 미완료 기능과 바이브코딩 실행 지침서 및 프로토콜의 부족한 요소를 객관적이고 과학적으로 종합 점검하여 향후 고도화 추진 근거를 마련함

## 1. 프로젝트 기능 구현 미완료 및 미흡 요소 상세 분석

실측 점검 및 프로덕션 준비 로드맵 문헌 검토 결과 아래 항목들이 미완료 또는 보완 필요 상태로 확인되었습니다.

1. 데이터 보안 및 이력 정리 미완료 (치명적 리스크)
   * primary_data 폴더 내 실제 WinCC OA 소스 코드(.pnl, .ctl, .xml) 및 레거시 데이터가 포함되어 있어 공개 저장소 환경에서 민감 정보 노출 위험이 상존함
   * cache/review_cache.json 등 로컬 개발 임시 경로 및 메타데이터가 git 이력에 남아 있어 git filter repo 등을 통한 과거 커밋 이력 완전 제거 작업이 필요함

2. 외부 독립 골든셋 v2 구축 및 정밀도 교차 검증 미완료
   * 현재 벤치마크 및 지표 측정은 개발팀 내부 라벨셋(ground_truth.json)을 기준으로 수행되어 정밀도 75.0%를 나타냄
   * 실제 현업 코드리뷰어 2인 이상이 참여하는 독립 교차 검증 골든셋(golden_set_v2) 구축과 라벨러 간 일치도(Cohen Kappa) 산출 작업이 미완료 상태임

3. AI 2차 리뷰 로컬 LLM 사양 확정 및 동시성 부하 테스트 미구현
   * config/settings.yaml 파일 내 model_id 값이 sane_local_llm 플레이스홀더로 남아 있어 실제 배포용 로컬 LLM 모델(Qwen2.5 Coder 등) 선정이 미확정됨
   * 동시 사용자 10인 이상 환경에서의 p95 응답시간 측정 부하 테스트가 미실시되었으며 장애 발생 시 사내 알림 웹훅 연동이 부재함
   * AI 페이로드 송신 시 설비명 및 태그명 마스킹 전처리 모듈이 미도입됨

4. CI CD 릴리즈 파이프라인 및 Executable 패키징 미비
   * release.yml 워크플로우 실행 이력 부재 및 v1.0.0 정식 버전 태그 미발행 상태임
   * Windows 무설치 단일 실행 파일(.exe) 자동 빌드 및 클린 환경 VM E2E 검증 파이프라인 미구현됨

5. 운영 거버넌스 및 카탈로그 관리 절차 미구현
   * 개발 체계가 단일 개발자와 AI 에이전트 위임 구조로 운영 중이므로 CODEOWNERS 2인 이상 지정이 시급함
   * 엑셀 룰 카탈로그 수정 시 동적 반영 외에 형상 변경 승인 프로토콜이 부재함

6. 추가 보완 필요한 전용 정적 파서 및 스키마 검증 기능
   * CTRL PNL 언어 전용 완전 구문 분석 파서(ANTLR4 또는 Lark 기반 AST) 미도입으로 정규식 및 부분 AST 분석 한계 존속
   * config/settings.yaml 의 Excel 셀 좌표 변경 시 사전에 구조 오류를 검지하는 Excel 스키마 린터(Linter) 미도입
   * 로컬 AI 동시 요청 제어를 위한 세마포어 기반 동시성 큐잉 및 AI 응답 TTL 캐시 갱신 엔진 미도입

## 2. 바이브코딩 지침서 및 프로토콜의 부족한 요소 분석

11번 바이브코딩 실행 지침서 및 vibe coding 스킬 지침을 점검한 결과 다음 부족 요소가 도출되었습니다.

1. 안티패턴 방지 스크립트의 vibe coding 스킬 미통합
   * vibe coding 스킬(SKILL.md)은 project_summarizer.py 호출만 안내할 뿐 11번 지침서의 핵심 자동 검증 스크립트(verify_ci_yaml.py, verify_benchmark_integrity.py, verify_coverage_claim.py)의 필수 실행 지침이 누락되어 있음

2. Diff 증빙(R1) 및 호출부 증명(R2)의 수동 의존성
   * R1과 R2 규칙이 보고서 작성자의 수동 git diff 및 grep 실행에 의존하고 있어 에이전트가 보고서를 작성할 때 누락하거나 거짓 서술할 가능성을 완전히 자동 차단하지 못함
   * 에이전트 완료 제출 시 자동으로 호출부 및 diff 유효성을 검사하는 CLI 검증 도구가 지침서에 미포함됨

3. 단일 출처(SSOT) 자동화 지침 부족
   * 수치 지표(Precision, Recall, p95 지연시간 등)가 여러 interim_reports와 PRD 및 README에 분산 기재될 때 불일치(AP 3 변형)가 발생할 가능성이 상존함
   * single_source_of_truth.json 지표 파일과 자동 동기화하는 지침이 지침서에 강제되어 있지 않음

4. Human in the Loop 승인 강제 장치 미흡
   * RuleOptimizer 기능이 오탐 룰 비활성화를 추천할 때 에이전트가 사람 검토자의 서면 승인 없이 임의로 룰을 끄는 행위를 기술적으로 차단하는 지침이 미흡함

## 3. 종합 향후 추진 계획

1. 보안 조치 Phase 0 실행: git 이력 재작성 및 primary_data 익명화 테스트 픽스처 전환
2. 독립 골든셋 구축 및 Critical High 룰 정밀도 85% 이상 실측 달성
3. vibe coding SKILL.md 업데이트를 통해 안티패턴 검증 스크립트 자동 실행 프로토콜 편입
4. R1 R2 검증 자동화 유틸리티 개발 및 단일 출처(SSOT) 지표 자동 동기화 체계 구축
5. CTRL 전용 정적 AST 파서 도입 및 엑셀 스키마 사전 린터 기능 추가 개발
