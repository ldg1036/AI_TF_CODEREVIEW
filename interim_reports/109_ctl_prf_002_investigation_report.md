# 109. CTL_PRF_002 (일괄 처리 미적용) 룰 구현체 취약점 진단 보고서

사용자님의 지적에 따라 `CTL_PRF_002` (내부 명칭: `MANUAL-003: 이벤트 교환 횟수 최소화`) 룰의 실제 소스코드 구현부(`check_batch_dp_operations`)를 정밀하게 재검사하였습니다. 

결론부터 말씀드리면, **사용자님의 우려대로 해당 룰의 현재 로직은 심각한 미탐(False Negative)을 유발할 수 있는 부실한 형태**임이 객관적으로 확인되었습니다. 상세한 원인은 다음과 같습니다.

## 1. 현재 로직의 치명적 결함 (과도한 면죄부 부여)

코드 378번째 라인을 보면 다음과 같은 로직이 존재합니다.
```python
if has_batch_pattern:
    // 일괄 처리가 잘 구현되어 있으므로 PASS (정상 준수 코드)
    return []
```
* **문제점**: 파일 전체에서 `dynAppend`를 활용한 일괄 처리 패턴이나 다중 인자 `dpGet` 패턴이 **단 한 번이라도 발견되면**, 해당 파일에 대한 검사를 즉시 중단하고 PASS를 반환해 버립니다.
* **영향**: 개발자가 A 함수에서는 일괄 처리를 잘 준수했으나, B 함수에서 단건 `dpSet`을 루프 안에서 100번 호출하는 악성 코드를 작성하더라도 이를 정상으로 판정하고 넘어가버리는 심각한 미탐 구멍이 존재합니다.

## 2. 구문 트리가 아닌 단순 텍스트 근접성에 의존

* **문제점**: 스코프 분석(AST)을 사용하지 않고, 오직 단건 `dpGet`/`dpSet` 함수가 **텍스트 상 15줄 이내에 3번 이상 등장**하는지만을 세어 클러스터링하고 있습니다.
* **영향**: 독립된 함수 내부에 있거나 `switch-case` 분기가 깊숙히 쪼개져 있는 경우에도, 라인 수가 15줄 이내로 가깝기만 하면 이를 묶어서 "왜 일괄처리 안했냐"며 오탐(False Positive)을 낼 우려가 있으며, 반대로 단건 호출이 16줄 간격으로 띄엄띄엄 배치되면 미탐(False Negative)으로 무시하게 됩니다.

## 3. 방법 선택의 타당성 결여 (정규식 기반의 한계)

앞서 우리가 무한 루프 탐지 및 `try_catch` 감지 등에 **Tree-sitter C++ AST 파서**를 도입하여 정밀도를 고도화했으나, 정작 이 성능 점검 룰(`CTL_PRF_002`)에는 아직 AST 제어 흐름 분석(CFA)이 맵핑되지 않은 상태로 방치되어 있었습니다.

## 4. 객관적 개선 방안 제안

사용자님의 통찰력 있는 지적이 맞았습니다. 이 룰은 텍스트 정규식 룰(`checker_registry.py`)에서 제거하고, AST 기반 룰(`ast_cfa_checker.py`)로 이관하여 다음 기준을 따르도록 재설계해야 합니다.

1. **전역 면죄부 폐지**: 파일 단위가 아닌 **스코프(함수 블록) 단위**로 일괄 처리 패턴을 개별 평가하도록 변경.
2. **AST 루프 노드 탐색**: `for`, `while` AST 노드의 자식 노드로 `dpGet` / `dpSet`이 포함되어 있는지 트리 구조로 정확히 감지.
3. **블록 내 연속 호출 카운팅**: 단순히 15줄이라는 텍스트 거리가 아니라, **동일한 StatementBlock 노드** 내부에 통신 연산이 3회 이상 등장할 때만 정확하게 감지.
