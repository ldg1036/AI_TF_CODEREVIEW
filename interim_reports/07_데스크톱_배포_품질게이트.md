# Python 데스크톱 앱 배포·품질 게이트

## 1. 목적과 적용 범위

이 문서는 웹서버를 설치하거나 HTTP 엔드포인트를 운영하지 않는 Python 데스크톱 응용프로그램의 릴리스 기준이다. GUI와 CLI는 동일한 Core 파이프라인을 호출하고, PyInstaller 패키지는 사용자의 PC에서 직접 실행된다.

## 2. 릴리스 전 필수 점검

### 2.1 기능·데이터 계약

- 체크리스트형 Client/Server Excel을 읽고, Excel SHA256·문서 버전·컴파일러 버전을 기록한다.
- 기존 체크리스트 행과 기술 메타데이터가 `parsed_rules`와 `review_applicability`로 분리 생성된다.
- Client 15/15, Server 20/20 기준 항목의 적용성 매핑이 해소되고 `unmapped == 0`이다.
- 미등록 checker, 잘못된 정규식, 필수값 누락, 파일 타입 불일치는 새 룰셋 전체 적용을 막고 직전 정상 룰셋을 유지한다.
- `.pnl/.xml/.ctl` 샘플의 인코딩 감지·canonical 변환·IR 생성·`parse_failed` 보고가 검증된다.

### 2.2 분석·리포트 및 AI 보안 정책

- 정적 룰만으로도 JSON/HTML 리포트가 성공적으로 생성된다.
- 기본 AI 프로바이더는 local (Qwen 2.5 Coder 3B / Ollama) 모드로 고정하며, 보안 승인 플래그(ALLOW_EXTERNAL_AI=true) 없이 클라우드 AI로 SCADA 코드가 전송되지 않도록 차단한다.
- AI 미설정, AI 타임아웃, WinMerge 미설치, Excel 출력 실패가 전체 실행 실패로 전파되지 않는다.
- 리포트에 원본/정규화 해시, 룰셋 버전, 적용성 상태, `run_id`, 단계별 metrics 및 자동화 커버리지 고지 배너(Client 33.3% / Server 30.0%)가 상시 포함된다.
- 파싱 실패 파일은 정상 위반 목록과 분리된 Errors 섹션에 표시된다.

### 2.3 자동수정 안전성

- 기본값은 자동수정 OFF이며 원본 파일은 절대 덮어쓰지 않는다.
- 수정 전 원본 해시와 anchor/context를 확인하고 syntax precheck와 정적 룰 회귀검사를 수행한다.
- 백업, 임시파일, atomic replace, 감사 로그가 순서대로 동작하고 검증 실패 시 수정본을 적용하지 않는다.

## 3. 데스크톱 실행 스모크

다음 시나리오를 서버 실행 없이 PyInstaller 산출물에서 확인한다.

1. 프로그램 실행 및 설정 파일 로딩
2. Client/Server Excel 선택과 컴파일 미리보기
3. `.ctl`, `.pnl`, `.xml` 파일 선택 및 확장자 기반 룰셋 라우팅
4. 정적 룰 실행, 진행률 표시, 오류 파일 표시
5. AI 미사용 상태에서 JSON/HTML/Excel 리포트 생성
6. WinMerge가 없을 때 `difflib` 폴백 실행
7. 선택적으로 AI 가이드·자동수정·Diff 검증 실행
8. 앱 종료 후 결과·로그·임시 작업공간 정리

## 4. 패키징 기준

- PyInstaller `onedir`을 기본 배포 형식으로 하고, `onefile`은 시작 시간과 백신 오탐을 검증한 경우에만 선택한다.
- 빌드에는 소스 Excel, 테스트 데이터, 개발용 비밀값, 임시 로그를 포함하지 않는다.
- `pywebview` 리소스, `openpyxl`, 인코딩 감지 라이브러리, 템플릿 파일이 패키지에서 정상 조회된다.
- 클린 PC 또는 개발 의존성이 없는 가상환경에서 설치·실행·리포트 저장을 확인한다.
- AI와 WinMerge는 선택 의존성으로 표시하고, 미설치 시 기본 정적검사가 동작해야 한다.

## 5. 성능·운영 게이트

- 동일 PC와 동일 샘플을 최소 3회 실행해 `collect`, `normalize`, `parse`, `static_rules`, `ai`, `diff`, `report`, `excel`, `total` 시간을 기록한다.
- 기준선 대비 p95가 20% 이상 악화되면 원인 분석 없이 릴리스하지 않는다.
- Excel 생성은 `defer_excel_reports` 옵션으로 UI 작업과 분리할 수 있어야 한다.
- `run_id` 작업공간에는 TTL과 최대 보관 개수를 적용하고, 동일 파일 동시 실행은 파일별 잠금으로 방지한다.

## 6. 보관할 릴리스 증적

다음 파일을 버전별로 보관한다.

- `release_gate.json`, `release_gate.md`
- Client/Server 적용성 매핑 및 커버리지 결과
- 성능 baseline과 최소 3회 실행 원자료
- 대표 `.ctl/.pnl/.xml` 입력과 JSON/HTML/Excel 샘플 리포트
- 테스트 명령·실행 환경·선택 의존성·미해결 TODO 목록

## 7. Go/No-Go 기준

다음 중 하나라도 미충족이면 릴리스하지 않는다.

- 핵심 데스크톱 스모크 실패
- Client/Server 매핑 누락 또는 `unmapped > 0`
- 원본 덮어쓰기 가능성이나 자동수정 검증 우회
- 클린 환경에서 실행 불가
- 기준선 대비 성능 20% 이상 악화 원인 미확인
- 결과 재현에 필요한 Excel·룰·프롬프트 버전 정보 누락

## 8. 설치·업데이트·복구 기준

- 프로그램 파일과 사용자 설정·캐시·로그·결과물 저장 위치를 분리한다.
- 설치·업데이트 전 배포물 버전과 SHA256을 기록한다.
- 업데이트 중 실패하면 이전 실행 가능 버전과 사용자 설정을 보존한다.
- 설정·룰 캐시가 손상되어도 직전 정상 룰셋 또는 기본 설정으로 복구할 수 있어야 한다.

## 9. 사용자 오류 안내 기준

오류 메시지는 내부 예외명만 표시하지 않고 `원인 → 영향 → 사용자 조치` 순서로 제공한다.

| 상황 | 사용자에게 표시할 조치 |
|---|---|
| Excel 양식 오류 | 시트·행·열·필수값과 수정 방법 표시 |
| 매핑 누락 | 해당 체크리스트와 필요한 `rule_id` 표시 |
| 파싱 실패 | 파일명·인코딩·실패 단계 표시, 해당 파일만 격리 |
| AI 실패 | 정적검사 결과는 유지하고 재시도·AI 제외 실행 제공 |
| WinMerge 미설치 | `difflib` 폴백 사용 여부 표시 |
| 권한·저장 실패 | 출력 경로와 권한 확인 방법 표시 |

## 10. 운영 지원 자료

릴리스에는 사용자 매뉴얼과 함께 로그 수집 방법, 오류 신고 양식, 지원 WinCC OA 버전, 룰 추가 요청 절차, 미지원 파일 형식 목록을 포함한다. 오류 신고 기본값은 원본 코드가 아니라 메타데이터·해시·`run_id` 중심으로 수집한다.
