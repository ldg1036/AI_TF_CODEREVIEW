# 최상위 등급(9.0+) 도약을 위한 중장기 고도화 로드맵

현재의 **우수(8.0~8.5)** 수준을 뛰어넘어, 글로벌 상용 정적 분석 도구(SonarQube, Coverity 등)에 준하는 **탁월(9.0 이상)** 수준으로 도약하기 위해 필요한 4대 핵심 개선 영역을 제안합니다.

---

## 1. 분석 엔진의 다차원화 (단일 파일 → 프로젝트 전체)

현재의 검사 엔진은 `ParsedFile` 하나만 바라보는 **단일 파일(Intra-procedural) 분석**에 머물러 있습니다. 이를 9점대로 올리려면 **파일 간 교차 분석(Inter-procedural / Cross-file Analysis)**이 필수적입니다.

* **[기능 제안] 모듈 링커(Module Linker) 및 의존성 그래프 도입**
  * `uses` 또는 `#uses` 지시문을 파싱하여 `.ctl` 라이브러리와 `.pnl` 패널 간의 의존성 그래프 구축.
  * **효과**: "A 라이브러리에 정의된 전역 변수를 B 패널에서 잘못된 타입으로 덮어쓰는 문제" 등 파일 간 경계를 넘나드는 위반을 잡아낼 수 있습니다.
  * **해결되는 룰**: `check_global_scope_shadowing`의 범위를 전역(프로젝트 전체)으로 확장.

## 2. 데이터 흐름 분석 (Data Flow Analysis, DFA) 도입

현재 트리시터(Tree-sitter)를 이용해 구조(AST)와 제어 흐름(CFA)까지는 분석하지만, **데이터 값의 상태 변화(Taint Tracking)**는 추적하지 못하고 있습니다.

* **[기능 제안] 오염 분석(Taint Analysis) 엔진 탑재**
  * 사용자 입력이나 외부 통신(`dpGet` 결과 등)이 안전한 검증(`if` 조건문 등)을 거치지 않고 SQL 쿼리나 파일 시스템 조작에 그대로 사용되는지 추적.
  * **효과**: 보안(SEC) 카테고리의 룰 정밀도가 기하급수적으로 상승합니다.
  * **해결되는 룰**: `sql_injection_risk`, `scada_security_exec`, `sprintf_buffer_overflow_risk`의 오탐률을 0%에 가깝게 낮출 수 있습니다.

## 3. 구조적 모듈화 및 플러그인 아키텍처 (아키텍처 9.0)

현재 33개의 체커 함수가 `checker_registry.py` 하나에 1,700줄 규모로 밀집되어 있어, 향후 룰이 100개 이상으로 늘어날 경우 유지보수 한계에 부딪힙니다.

* **[기능 제안] 디렉토리 기반 동적 플러그인 로더**
  * `app/core/rules/checkers/` 하위에 `performance.py`, `security.py`, `resources.py` 등으로 물리적 파일을 분리.
  * 시스템 구동 시 해당 폴더의 클래스들을 리플렉션(Reflection)이나 메타클래스로 자동 스캔 및 레지스트리 등록.
  * **효과**: 룰 개발자들이 다른 체커의 코드를 건드릴 위험 없이 독립적으로 룰을 개발하고 플러그인처럼 붙일 수 있습니다.

## 4. 개발자 경험(DX) 및 실운영 투입 준비도 (프로덕션 9.0)

현재 파이프라인은 CI/CD 환경이나 CLI에서 한 번에 묶음으로 돌아가는 배치(Batch) 방식입니다.

* **[기능 제안 1] 점진적 분석(Incremental Analysis) 및 Git Diff 통합**
  * 1,000개의 파일이 있는 프로젝트에서 1개의 파일만 수정했을 때, 수정된 파일과 그 파일을 참조하는 파일만 빠르게 골라서 검사.
* **[기능 제안 2] Language Server Protocol (LSP) 인터페이스 추가**
  * 파이프라인의 결과를 VSCode나 외부 편집기에 실시간 빨간 줄(Lint Error)로 띄워줄 수 있는 데몬 프로세스 지원.
* **[기능 제안 3] 오탐 피드백 자가 학습 루프**
  * 개발자가 "이건 오탐이다(False Positive)"라고 웹 UI에서 마킹하면, 해당 코드 스니펫의 AST 구조를 수집하여 유사한 패턴에서는 AI 검증이 자동으로 면제되도록 룰셋을 동적 튜닝.

## 🎯 요약: 9점을 위한 Next Action Plan

만약 지금 당장 9점 도약을 위한 개발에 착수한다면, 투자 대비 효과(ROI)가 가장 높은 **1단계 목표**는 다음과 같습니다.

1. `checker_registry.py`의 **플러그인 아키텍처 물리적 분할** (구조적 우아함 확보)
2. **프로젝트 단위 전역 스캐너 구축** (Cross-file Analysis 기반 마련)
3. 변경된 파일만 검사하는 **Git Diff 기반 점진적 스캔** 로직 추가 (실행 속도 극대화)

이러한 개선이 이뤄지면, 단순한 사내 자동화 스크립트를 넘어 상용 정적 분석 솔루션 레벨의 위상을 갖추게 될 것입니다.
