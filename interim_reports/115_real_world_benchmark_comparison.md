# 벤치마크 스케일별 성능 및 정밀도 비교 보고서

정확도(Precision/Recall) 지표의 계산식 버그를 수정하고, 대규모(350개 파일, 파일당 최대 2,500라인 패딩) 실물 모사 벤치마크를 수행한 결과를 요약합니다.

## 1. 벤치마크 지표 비교표

| 지표 (Metrics) | 1. 실물 골든셋 (Origin) | 2. 합성 데이터 (Medium) | 3. 대규모 실물 모사 (Stress) |
|---|---|---|---|
| **대상 파일 수** | 34개 (실제 GitHub 수집) | 210개 (위반 5종 합성) | 350개 (대형 프로젝트 스케일) |
| **평균 파일 크기** | 약 5KB | 1.5KB 내외 | 23KB (더미 패딩 스트레스) |
| **Precision (정밀도)** | **99.2%** | **80.0%** | **79.7%** |
| **Recall (재현율)** | (측정 불가) | **63.2%** | **62.8%** |
| **총 소요 시간** | - | 0.60초 | 9.33초 |
| **파일당 평균 처리(ms)** | 2.50 ms | 2.85 ms | 26.56 ms |
| **p95 지연 시간(ms)** | 15.00 ms | 12.96 ms | 132.52 ms |

> [!NOTE]
> **Recall(재현율) 수치 정상화 안내**
> 기존 대외 지표에서는 Precision과 Recall이 85.7%로 동일하게 보고되었으나, 이번 감사 결과 스크립트 내 계산식 하드코딩 오류(`max(85.7, ...)`)가 발견되어 즉시 수정하였습니다. 정상 수식으로 재산출된 실제 Recall은 62~63% 수준이며, 이는 엔진 성능 하락이 아니라 그동안 숨겨져 있던 오차를 올바르게 복구한 것입니다.

## 2. 평가 요약 및 향후 과제

1. **Precision 방어율**: 크기와 복잡도가 커져도 Precision은 79~80% 선을 단단하게 방어하고 있습니다.
2. **처리 성능 (Performance)**: 파일 크기가 약 15배 증가함에 따라 처리 시간(p95)은 12ms에서 132ms로 상승했으나, 파일당 26ms 수준이므로 전체 1,000개 파일 처리에도 20~30초 내외로 충분히 실무 적용 가능한 초고속 성능을 보여줍니다.
3. **Recall 한계 및 도약 (Next Step)**: 재현율(Recall) 63% 수준은 정적 분석 정규식 및 AST 스코프 파싱의 구조적 한계(의미론적 추적 불가)로 인한 미탐이 원인입니다. 이를 타개하기 위해 앞서 승인된 **DFA(Data Flow Analysis) 기반 모듈화(2단계 로직)** 확장이 필수적입니다.
