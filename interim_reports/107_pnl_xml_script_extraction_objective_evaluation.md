## 1. 평가 목적 및 명시적 가정

**가정(Assumption)**
* WinCC OA의 화면 패널(.pnl) 및 설정 파일(.xml)은 수천 줄의 UI 컴포넌트 메타데이터(크기, 색상, 레이아웃)와 임베디드 제어 스크립트(Initialize, Click 등)가 혼재되어 있습니다. 정적 코드 리뷰가 유의미하려면 UI 노이즈를 완벽히 제거하고 **순수 제어 스크립트만 원본 라인 번호를 유지한 채 추출**해야 한다고 가정합니다.

---

## 2. 방법 선택의 타당성 (Methodological Validity)

**도입 방법 1: 계층적 XML 트리 파싱 (`xml_parser.py` 및 XML PNL)**
* **타당성**: 파일이 표준 XML 형식을 따를 경우 `xml.etree.ElementTree`를 사용하여 안전하게 구문 트리를 생성합니다. `<script>`, `<event>` 태그 하위의 텍스트 노드만 순회하여 추출하므로 정규식 파싱 시 발생할 수 있는 오탐을 원천 차단하는 과학적으로 가장 안정적인 접근법입니다.

**도입 방법 2: 중괄호 균형 탐색 기반 텍스트 폴백 파싱 (`pnl_parser.py`)**
* **타당성**: WinCC OA 레거시 PNL 텍스트 포맷은 표준 XML이 아니므로 정규식이 필요합니다. 그러나 단순히 정규식 매칭을 쓰지 않고 **중첩 중괄호 균형(Brace Balancing) 카운팅 알고리즘**을 도입하였습니다. 스크립트 내부에 `if`나 `for` 문이 중첩되더라도 닫히는 괄호를 정확히 인지하여 스크립트 본문이 중간에 잘려나가는 치명적인 결함을 방지한 훌륭한 설계입니다.

**도입 방법 3: 라인 번호(Line Number) 보존 아키텍처 및 UI 객체 완벽 제거**
* **타당성**: 코드 리뷰 자동화의 핵심은 VCS(Git) 코멘트 작성 시 정확한 라인 지적입니다. 파서의 추출 로직은 `<shape>`, `<properties>`, `V 2`, `CB 1` 등과 같은 **비-스크립트 UI 메타데이터 영역을 완전히 빈 줄(Empty line)로 치환**합니다. 이를 통해 원본 파일과 추출된 스크립트 간의 1:1 라인 매핑 무결성을 보장하는 동시에, UI 객체로 인해 AI 또는 정규식이 오작동(False Positive)하는 노이즈를 100% 제거하는 아키텍처를 구현하였습니다.

## 3. 검증 결과 및 신뢰성 지표

해당 기능에 대한 유닛 테스트(`test_pnl_parser.py`, `test_xml_parser.py`) 검증 지표는 다음과 같습니다.

* **인코딩 무결성 대응**: CP949 / EUC-KR로 저장된 과거 레거시 패널 파일들에 대해 디코딩 폴백(Fallback) 방식을 적용하여 깨짐 없이 파싱 성공을 실측 확인.
* **오류 복원력**: 존재하지 않는 파일이나 손상된 XML에 대해 파이프라인 중단 없이 `parse_failed` 상태 모델을 반환하여 시스템 가용성을 유지함.

---

## 4. 객관적 한계점 보고 (Limitations)

1. **난독화된 텍스트 PNL 주석 내 비대칭 괄호 한계**
   * 레거시 텍스트 포맷 PNL을 분석할 때, 개발자가 주석(Comment) 내부에 열리는 중괄호 `{` 기호를 비대칭적으로 대량 작성해둔 특수 엣지케이스의 경우, 중첩 카운팅 알고리즘이 닫히는 스코프를 오판할 수 있는 정적 텍스트 기반 파서의 근본적 한계가 존재합니다.

---

## 5. 종합 결론 (Conclusion)

본 PNL/XML 스크립트 추출 모듈은 구조적 XML 파싱과 텍스트 균형 탐색을 결합한 유연한 폴백 구조를 지니고 있습니다. 특히 원본 라인 번호 보존을 통해 VCS 리뷰 코멘트의 정확성을 사수했다는 점에서 실무 적용 타당성이 매우 높게 평가됩니다. 극히 이례적인 주석 내 괄호 비대칭 상황 외에는 제어 코드만을 완벽하게 분리해내는 엔터프라이즈급 신뢰성을 갖추었습니다.
