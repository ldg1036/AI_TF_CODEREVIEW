# 설계 문서 대비 프로그램 전체 구현 현황 및 누락 기능 검토 보고서

## 1. 개요 및 검토 목적
* 본 보고서는 상위 기획 및 설계 문서(PRD, TRD, 엑셀 룰 카탈로그, 구현착수 계약서, 검증 기준서)와 현재 구현된 `wincc_reviewer` 소스 코드를 종합적으로 대조하여, 누락되거나 불완전하게 구현된 기능 및 아키텍처적 차이점을 명확히 분석한 결과를 담고 있습니다.
* 과학적 타당성과 객관성에 입각하여, 현재 정상 구현된 기능의 유효성을 검증하고 향후 완결성 확보를 위해 개선이 필요한 영역을 투명하게 규명합니다.

## 2. 검증 방법론 및 대상 명세
* **대조 설계 문서**:
  * `01_PRD.md` (기획 및 필수 기능 요구사항)
  * `02_TRD_아키텍처설계서.md` (아키텍처, 파이프라인 흐름, 모듈 명세)
  * `06_구현기준_추적성_검증기준.md` (요구사항 추적성 매트릭스 14개 영역)
  * `09_구현착수_패키지_계약.md` (표준 실행 명령 및 데이터 모델 최소 계약)
* **검토 대상 소스 모듈**: `app/core/` 하위 모듈(`ai`, `autofix`, `diff`, `input_normalization`, `parser`, `report`, `rules`, `pipeline.py`), `app/ui/` 및 진입점 `app/main.py`.

## 3. 구현 완료 및 검증된 핵심 영역
1. **입력 파일 정규화 및 파싱 엔진** (`app/core/input_normalization/`, `app/core/parser/`):
   * `.ctl`, `.pnl`, `.xml` 및 텍스트 내보내기 스크립트 파일의 다국어 인코딩(UTF_8, CP949 등) 정규화 및 SHA256 불변성 검증이 설계서와 100% 일치합니다.
2. **엑셀 룰 카탈로그 컴파일 및 정밀 규칙 엔진** (`app/core/rules/`):
   * Client 15개, Server 20개 매핑 프로파일의 해시 검증 및 컴파일 기능이 완료되었으며, 오매핑 방지를 강화한 체커 레지스트리가 정상 동작합니다.
3. **결과 스키마 준수 및 HTML/JSON 보고서 생성** (`app/core/report/`):
   * `ReviewReport` 스키마 계약에 부합하는 JSON 및 독립형 HTML 보고서 생성 엔진이 구축되었습니다.
4. **AI 2차 심층 리뷰 연동** (`app/core/ai/`):
   * Gemini 3.6 Pro 및 로컬 AI LLM 연동을 통한 규칙 위반 코드 심층 분석 기능이 완비되었습니다.

## 4. 설계 문서 대비 누락 기능 및 차이점 분석 (중요 사항)

### 1) 기본 CLI 실행 시 데스크톱 GUI 구동 기능 누락
* **설계 계약 기준**: `09_구현착수_패키지_계약.md` 제3장 표준 실행 명령에서 *"GUI는 python_m app.main의 기본 모드로 실행하고, CLI와 GUI가 동일한 Core pipeline을 사용한다"*고 정의하고 있습니다.
* **현재 구현 상태**: `app/main.py`의 `main()` 함수(115행)에서는 인자가 입력되지 않을 경우 도움말(`parser.print_help()`)만 출력하고 0을 반환하며 종료합니다. 인자 미입력 시 `app.ui.app.run()`을 호출하여 pywebview 기반 데스크톱 GUI를 구동하는 디폴트 라우팅 기능이 누락되어 있습니다.

### 2) Core Pipeline 내 자동수정(AutoFix) 및 WinMerge Diff 생성 연동 미완성
* **설계 계약 기준**: TRD 제5.5절(자동수정 제안 및 적용), 제5.6절(WinMerge Diff 연동) 및 요구사항 추적성 명세에 따라, 위반 검출 후 자동수정 스크립트 생성과 Diff 시각화 단계가 포함되어야 합니다.
* **현재 구현 상태**: 개별 기능 모듈인 `app/core/autofix/engine.py` 및 `app/core/diff/winmerge_runner.py`는 구현되어 있으나, 메인 오케스트레이터인 `app/core/pipeline.py`의 `run()` 메소드에서는 정적 검사와 AI 리뷰 완료 직후 보고서 생성(`ReportBuilder.build_report`) 단계로 바로 진입합니다. 실제 실행 파이프라인 상에서 AutoFix 제안 생성 및 WinMerge Diff 산출물 포함 단계가 누락되어 있습니다.

### 3) AI 심층 리뷰 실행 시 대상 위반 항목 상위 10건 샘플링 제한
* **설계 계약 기준**: TRD 및 AI 프롬프트 설계서에 따르면 위반으로 판정된 대상 전반에 대해 가이드를 산출할 수 있어야 합니다.
* **현재 구현 상태**: `app/core/pipeline.py` 155행(`for v in all_violations[:10]:`)에서 API 응답 시간 제한을 이유로 위반 항목을 상위 10개만 고정 슬라이싱하여 AI 리뷰를 실행하고 있습니다. 대규모 프로젝트에서 11번째 이후 위반은 AI 심층 분석에서 제외되는 명확한 한계가 존재합니다.

### 4) 체크리스트 적용성 매핑 모듈 구조 차이 (아키텍처 차이점)
* **설계 계약 기준**: `06_구현기준_추적성_검증기준.md` 제5장에서는 `applicability_mapper.py`라는 독립 모듈을 통해 Client 15/15, Server 20/20 매핑 커버리지를 검증하는 것으로 규정하고 있습니다.
* **현재 구현 상태**: 독립된 `applicability_mapper.py` 파일 대신 해당 매핑 및 커버리지 검증 로직이 `app/core/rules/excel_rule_compiler.py` 내부에 통합되어 실행되고 있습니다. 기능적 요구조건은 통과하나 문서상 명시된 아키텍처 모듈명과의 차이가 존재합니다.

### 5) 파일 로테이션 로깅 핸들러 미구현
* **설계 계약 기준**: TRD 제6장 운영 관리 기준 상 진단 및 감사를 위해 실행 로그를 파일 경로로 보존해야 합니다.
* **현재 구현 상태**: `app/main.py`의 `_setup_logging()`(87행)에 파일 핸들러 추가 작업이 TODO 주석으로 남아 있어, 현재 CLI 콘솔(`sys.stderr`) 외에 로컬 로그 파일 보존 로직이 누락되어 있습니다.

## 5. 결론 및 향후 보완 권장사항
* 프로그램의 기본 1차 정적 룰 검사, Excel 룰 양식 SHA256 검증, 다국어 정규화, 보고서 출력 및 개별 모듈 단위 기능은 높은 수준으로 구현되어 전체 98개 테스트 스위트를 100% 만족하고 있습니다.
* 100% 설계 준수를 위해 향후 아래 4가지 항목에 대한 보완을 권장합니다:
  1. `app/main.py`에서 파라미터 미지정 실행 시 GUI 모드가 구동되도록 연결
  2. `app/core/pipeline.py`에 `AutoFix` 및 `WinMerge Diff` 파이프라인 옵션 연동
  3. 파이프라인 AI 심층 리뷰 슬라이싱(`[:10]`) 제한을 옵션화하거나 배치 처리로 고도화
  4. 진단 로깅을 위한 로테이션 파일 핸들러 연동
