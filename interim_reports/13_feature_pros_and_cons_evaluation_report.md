# 코드리뷰 자동화 프로그램 기능별 장단점 및 과학적 타당성 평가 보고서

## 1. 평가 개요 및 목적
* 본 보고서는 WinCC OA 코드리뷰 자동화 프로그램(WinCC Reviewer)의 전체 아키텍처와 세부 기능군을 대상으로, 각 기능이 도출하는 장점(과학적 유효성 및 운용 효율성)과 단점(구조적 한계 및 향후 보완 과제)을 투명하고 객관적으로 평가합니다.
* 평가 방법론은 소프트웨어 공학의 정적 분석 타당성, 실행 시간 효율성, 지식 증강 모델의 정확도, 유지보수성 지표를 적용하였습니다.

## 2. 기능별 장단점 정밀 분석

### 가. 정규식 및 키워드 기반 고속 정적분석 엔진 (Rule Engine)
* **기능 요약**: Excel 기반 룰 카탈로그(Client 15개, Server 20개 항목)와 동적 연동되어 파일별 위반 사항을 검출하고 심각도 등급을 산출합니다.
* **장점 (Pros)**:
  * **초고속 검사 속도**: 파일 수정 시각(mtime) 기반 메모리 캐싱 및 컴파일 정규식 풀링을 적용하여 대량 프로젝트 파일 검사 시 0.01초 내외의 응답 속도를 보장합니다.
  * **운용 유연성**: 룰셋 정의를 코드 하드코딩이 아닌 Excel 양식(`schemas/client_ruleset.xlsx`, `schemas/server_ruleset.xlsx`)에 분리하여 현업 엔지니어가 즉시 검사 규칙을 갱신할 수 있습니다.
  * **다국어 인코딩 강건성**: `utf_8_sig`, `cp949`, `utf_8` 자동 판정 메커니즘을 갖추어 레거시 프로젝트 스크립트에서도 파싱 실패를 최소화합니다.
* **단점 (Cons) 및 한계**:
  * **문맥 및 상태 미인지**: 단순 정규식 패턴 기반이므로 변수의 재할당 흐름이나 조건 분기문 내 간접 호출 등을 추적하지 못해 다소의 과검출(False Positive) 또는 미검출(False Negative)이 발생할 수 있습니다.
* **보완 방향**: AST 제어 흐름 분석 체커와의 유기적 병행 검사를 통해 문맥 인지 수준을 보완하고 있습니다.

### 나. AST 기반 심층 제어 흐름 분석(Control Flow Analysis) 모듈
* **기능 요약**: 스크립트의 추상 구문 트리(AST)와 제어 흐름을 순회하여 `dpConnect` 콜백 함수 심볼 검증, 매개변수 시그니처 정밀 검증, 무한 루프 도달 가능성을 분석합니다.
* **장점 (Pros)**:
  * **의미론적 결함 조기 차단**: 콜백 함수 미선언(`CTL_AST_CFA_001`), 규격 미달 매개변수(`CTL_AST_CFA_002`), 데드락 위험이 있는 무한 루프 탈출 제어문 누락(`CTL_AST_CFA_003`) 등 고질적 런타임 오류를 사전에 식별합니다.
  * **주석 기만 방지**: 루프 내 `break`나 `return` 검색 시 주석행 내의 문자열을 필터링하여 기만적인 매칭 오류를 차단하는 높은 타당성을 확보했습니다.
* **단점 (Cons) 및 한계**:
  * **단일 파일 스코프 한계**: 현재 모듈 수준 심볼 검사는 개별 파일 내부 선언문을 중심으로 이루어지므로, 전역 인클루드 라이브러리에 선언된 콜백 호출의 경우 프로젝트 단위 심볼 링크 테이블이 없으면 미선언 위반으로 판정될 수 있습니다.
* **보완 방향**: 향후 다중 파일 프로젝트 전역 심볼 테이블 매핑 모듈으로 확장할 필요가 있습니다.

### 다. WinCC OA 도메인 특화 AI/RAG 심층 리뷰 및 Safe Code 변환
* **기능 요약**: `dpConnect`, `dpGet`, `dpSet` 등 공식 API 매뉴얼 사서함(RAG)을 문맥으로 주입하고, 완결된 1:1 Safe Code를 도출하는 Few_Shot 프롬프트 기반 LLM(Gemini 3.6 Pro) 리뷰 엔진입니다.
* **장점 (Pros)**:
  * **할루시네이션 극소화**: WinCC OA 도메인의 고유 API 프로토타입과 에러 처리 권장사항을 프롬프트에 동적 삽입함으로써 일반 모델의 오안내를 방지합니다.
  * **실행 가능한 대안 제시**: 단순 지적이 아닌 `if (rc != 0)` 에러 처리가 포함된 1:1 대체 코드(`autofix_candidate`)를 제공하여 수정 비용을 절감합니다.
  * **보안 환경 호환성**: 오프라인 및 로컬 LLM 폴백 인터페이스를 제공하여 폐쇄망 공정 환경에서도 안심하고 사용할 수 있습니다.
* **단점 (Cons) 및 한계**:
  * **응답 시간 지연**: LLM 통신 및 지식 탐색 과정에서 수 초 이상의 대기 시간이 소요되어 초고속 정적 엔진 대비 검사 시간이 증가합니다.
  * **결정론적 한계**: LLM 생성 텍스트의 본질적인 확률성으로 인해 반환된 코드는 반드시 자동 테스트나 인간의 검토(Human_in_the_Loop)를 통한 인준이 필요합니다.

### 라. 3중 다형성 리포트 (HTML / CSV / JSON) 및 WinMerge Diff 연동
* **기능 요약**: 단일 HTML 내 인터랙티브 바닐라 JS 필터와 WinMerge Diff를 통합하고, CSV 내보내기 시 Excel 체크리스트 추적성 정보를 함께 산출합니다.
* **장점 (Pros)**:
  * **외부 의존성 제로**: HTML 보고서는 CDN 라이브러리 없이 독립 구동하며, 심각도 필터링 및 실시간 키워드 검색을 브라우저 메모리 내에서 0.01초 만에 실행합니다.
  * **추적성 무결성**: CSV 내보내기 시 `CHECKLIST_TRACEABILITY` 구분 행을 통해 사내 표준 체크리스트(Client 15개, Server 20개) 매핑 정보를 누락 없이 전달하며 BOM 첨부로 한글 깨짐을 예방합니다.
  * **장애 격리성**: 파싱 실패 파일(`parse_failed`)을 독립된 Errors 섹션에 격리하여 통계가 왜곡되지 않는 투명한 분석 결과를 보고합니다.
* **단점 (Cons) 및 한계**:
  * **외부 도구 의존성 옵션**: WinMerge 실행 파일이 없는 컴퓨터 환경에서는 Python `difflib` 기반 텍스트 Diff로 폴백되므로 GUI 비교 툴의 고급 편의 기능은 제한됩니다.

### 마. pywebview 기반 경량 데스크톱 UI 및 단일 실행 배포
* **기능 요약**: 백엔드 웹 서버 없이 Python 함수와 프론트엔드 JS가 직접 통신하는 로컬 바인딩 구조 및 PyInstaller 단일 패키징 시스템입니다.
* **장점 (Pros)**:
  * **자원 효율성 및 충돌 차단**: 웹 서버(FastAPI 등)를 구동하지 않아 로컬 포트 충돌, 방화벽 거부, 불필요한 메모리 소모를 완벽히 해결했습니다.
  * **배포 신속성**: 파이썬 인터프리터 설치 없이 윈도우 단일 실행 파일(`.exe`)만 배포하여 현업 공정 컴퓨터에 즉각적인 적용이 가능합니다.
* **단점 (Cons) 및 한계**:
  * **운영체제 웹뷰 런타임 종속**: 윈도우의 WebView2 등 시스템 내장 렌더러에 의존하므로 OS 업데이트 상태에 따라 극히 미세한 렌더링 차이가 나타날 수 있습니다.
  * **단일 사용자 데스크톱 한계**: 여러 사용자가 웹상에서 협업하는 중앙 집중형 서버 아키텍처가 아니므로 다중 사용자 동시 스캔 서비스가 필요한 경우 웹 아키텍처로의 전환이 요구됩니다.

## 3. 종합 평가 및 결론
* 현재 프로그램은 고속 정적 검사의 효율성과 AST/AI 도메인 RAG의 정밀성을 상호 보완적으로 결합한 다층적(Multi_layer) 아키텍처를 취하고 있습니다.
* 정적 검사의 한계(문맥 미인지)는 AST CFA 및 AI 심층 리뷰로 해결하고 있으며, AI의 한계(속도 및 확률성)는 정적 검사의 전처리 필터링 및 자동화된 Safe Code 양식으로 제어하여 과학적 타당성과 실전 생산성을 모두 입증하였습니다.
